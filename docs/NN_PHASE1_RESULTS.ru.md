## 3. Почему 1.6 не включён по умолчанию

`mt_speculate_ab.py`, he‑ru, фразы 12–36 слов: принято 80 % предложенных токенов, время ×0.81 (медиана по парам ×0.83); для коротких he‑en фраз выигрыш ≈ 5 %. Но текст совпадает с обычным жадным декодированием только в 32 из 43 случаев (расхождения в околоравных логитах bf16 между батчем и одиночным шагом: точка в конце, синоним). Формулировка плана требует ≥ 99.5 % токенов и нуля материальных отличий, поэтому пункт перенесён в категорию «меняет вывод» и требует метрики качества на корпусе. Стоимость прохода по M токенов с тёплым кэшем (`mt_batch_cost.py`): 1 токен 30 мс, 4 — 43, 8 — 77, 16–32 — 100–110 мс.

- Выигрыш по первому видимому черновику 3–5 %, по лагу закрытого перевода 4–6 %, по первому готовому переводу 8 %, по первому токену перевода 29 %. Гейт «≥ 10 %» из плана относился к опциям Блока B2, а не к этим изменениям; по общей задержке выигрыш небольшой, потому что при 1× время определяется расписанием снимков (≈ 2.4 с), а не вычислениями.
- Прерывание устаревших обновлений (1.2) снижает стирание на ≈ 40 % (p50 1.42 → 0.86, p95 2.58 → 1.91) и очередь ASR на ≈ 90 %; без него стирание как у `stock`.
- `asr_duration` не изменился (p50 0.48 с во всех вариантах; отдельное включение текста без таймингов слов даёт −1.5 % по p50 и −4 % по p95), потери речи те же.
- Петли (1.8) в этом отрезке редки, на 7 минутах эффекта не видно; он есть на проблемных окнах (§1, строка 1.8).
- Ошибка, найденная этим прогоном: быстрый цикл `mt_generate` строил потоковый детокенайзер дважды за вызов (`hasattr` вычисляет свойство), по 0.10 с каждый. В первом прогоне это давало первый кусок перевода на 0.1 с позже `stock` (p50 0.35 против 0.25 с), хотя первый токен генерации был быстрее (0.15 против 0.25 с). Исправлено: один детокенайзер на токенайзер плюс `reset()`; идентичность 84/84, в изоляции первый кусок 0.213 против 0.274 с у `stock`, весь перевод 0.736 против 0.804 с.
- Метрика `stable_word_seconds` (p50 по 183 словам из 11 групп) нестабильна: она перескакивает между 11.4 и 14.6 с у одинаковых вариантов (в одной серии `stock` дал 14.54, а быстрая генерация 11.39), потому что медиана лежит на границе двух больших групп. Разбор по группам идентичен у `stock` и быстрой генерации (самая большая группа: 24.6–25.0 с, следующая 14.5–14.9 с). Для решений её использовать нельзя, пока нет больше групп.
