## 3. Почему 1.6 не включён по умолчанию

`mt_speculate_ab.py`, he‑ru, фразы 12–36 слов: принято 80 % предложенных токенов, время ×0.81 (медиана по парам ×0.83); для коротких he‑en фраз выигрыш ≈ 5 %. Но текст совпадает с обычным жадным декодированием только в 32 из 43 случаев (расхождения в околоравных логитах bf16 между батчем и одиночным шагом: точка в конце, синоним). Формулировка плана требует ≥ 99.5 % токенов и нуля материальных отличий, поэтому пункт перенесён в категорию «меняет вывод» и требует метрики качества на корпусе. Стоимость прохода по M токенов с тёплым кэшем (`mt_batch_cost.py`): 1 токен 30 мс, 4 — 43, 8 — 77, 16–32 — 100–110 мс.

## 4. Сквозной повтор записи на 1×: не выполнен

Первый раунд повтора (6 минут записи, варианты `stock`, `phase1`, `phase1_no_interrupt`) прошёл при нехватке оперативной памяти и работающем своп‑файле (и параллельно с работой пользователя на этом Mac): ASR занимал 1.3–1.5 с вместо 0.45 с даже у `stock`, первый черновик появлялся через 6–16 с вместо 2.5 с в исходной записи. Эти числа непригодны для сравнения вариантов и в отчёт не включены; прогон остановлен по просьбе пользователя. `experiments/corpus/e2e_ab.py` теперь не запускает прогон, пока давление памяти не нормальное (свободно ≥ 40 %), а CPU не простаивает ≥ 60 % (`gated.wait_until_quiet`). Его нужно выполнить на свободном Mac (например, ночью, ≈ 25 мин на прогон при двух моделях в памяти ≈ 4.4 ГБ MLX), чтобы подтвердить эффект 1.1/1.2 на TTFV и p95 задержки; до этого эффект по задержкам подтверждён только отдельными замерами аудита (Приложение А плана) и тестами поведения.
