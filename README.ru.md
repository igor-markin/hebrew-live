# Hebrew Live CLI — краткая инструкция

Локальные субтитры на иврите и перевод на целевой язык, поддержанный
активной локальной моделью, для Mac с Apple Silicon. После одноразовой загрузки
моделей распознавание, перевод, запись аудио, история и браузерный интерфейс
работают на Mac без облачного inference.

**Поддерживается только Apple Silicon.** Распознавание и перевод выполняются через MLX
на Apple GPU с Metal. Python-координатор и Silero VAD используют также CPU; это не
означает, что все операции идут на GPU. Запасного пути через Intel, Rosetta, Linux,
Docker, CPU-inference, CUDA или облако нет.

Это **кандидат в public alpha**, а не стабильный релиз. Собственный код лицензирован
по [Apache License 2.0](LICENSE). Лицензия кода не распространяется на веса моделей,
шрифты и другие сторонние материалы. До заявления о готовности релиза остаются
проверки из [docs/THIRD_PARTY.md](docs/THIRD_PARTY.md) и
[docs/RELEASE_READINESS.md](docs/RELEASE_READINESS.md).

## Требования

- Mac с Apple Silicon (`arm64`), нативный терминал без Rosetta и поддерживаемая Apple
  версия macOS;
- `uv`; при первом запуске он может явно, после подтверждения, получить CPython 3.12 и
  установить зафиксированные зависимости;
- микрофон для `listen`;
- современный Safari или Chromium с JavaScript и доступом к `127.0.0.1`.

Формальная матрица версий браузеров и чистая проверка на другом Mac ещё не проведены.
Node.js 24 нужен только разработчику для пересборки интерфейса.

## Установка из чистого публичного экспорта

После установки [`uv`](https://docs.astral.sh/uv/) распакуй архив и в интерактивном
Terminal выполни одну команду:

```sh
./run.sh
```

При первом запуске launcher отдельно спрашивает разрешение на сетевую установку Python
и зависимостей, проверяет macOS, нативный `arm64` и реальный доступ MLX к Metal, выводит
источники и ссылки на условия моделей, а затем отдельно спрашивает о загрузке базового
набора примерно на 5,1 ГБ. Отказ или отсутствие интерактивного ввода останавливают
процесс до загрузки весов. `uv`, Homebrew и системные программы launcher не ставит.

Для одного неинтерактивного запуска сначала прочитай
[условия и реестр моделей](docs/THIRD_PARTY.md), затем явно выполни:

```sh
./run.sh --accept-model-terms
```

Передача этого флага — явное подтверждение, что ты ознакомился со ссылками на источники
и условия моделей и запрашиваешь загрузку. Команда готовит зафиксированное окружение,
загружает базовые модели и запускает `listen`; флаг не меняет upstream terms и не
сохраняет отдельную юридическую запись о принятии. Без терминала или этого флага
автоматической загрузки весов нет.

Отдельные команды для проверки и восстановления остаются прежними:

```sh
./run.sh model-info
./run.sh languages
./run.sh setup --accept-model-terms
./run.sh doctor
./run.sh listen
```

Управляемая модель перевода — MiLMMT; setup не загружает альтернативный переводчик.

Сеть нужна для первой установки зависимостей и `setup`. После подготовки окружения все
остальные команды через `run.sh` запускают `uv` и модели в offline-режиме. Облачного
запасного маршрута нет.
`model-info` без загрузки показывает source, ссылку на условия/свидетельство и
замечание по каждому компоненту; команда доступна и из установленного wheel. Перед
загрузкой `setup` повторяет эту информацию. Флаг подтверждения только защищает от
случайной большой загрузки; он подтверждает ознакомление и запрос на скачивание, но не
меняет условия поставщиков и не сохраняет отдельную юридическую запись.

Перед каждым запуском выполняется read-only проверка
`uv sync --frozen --offline --check`. Один Python executable в управляемом окружении, оставшийся после
прерванного sync, не считается готовым окружением. Если `.venv` неполна или перестала
соответствовать `pyproject.toml` и `uv.lock`, интерактивный запуск отдельно спрашивает
разрешение на восстановление. Для осознанного неинтерактивного ремонта зависимостей
можно выполнить, например, `./run.sh --bootstrap model-info`: `--bootstrap` не
подтверждает ознакомление с условиями моделей и не скачивает веса. Ошибка sync сохраняет
свой код, а следующая попытка снова требует разрешения.

`run.sh` входит в allowlisted source export и sdist. В wheel launcher не нужен:
установленное Python-окружение предоставляет команду `he-ru`; она применяет ту же
проверку платформы и Metal перед setup, doctor или inference.

Для установки не обязателен реестр пакетов. `uv tool install` принимает локальный
каталог Python-проекта или Git source и создаёт постоянное изолированное окружение.
Из проверенной локальной копии:

```sh
uv tool install --python 3.12 /полный/путь/hebrew-live
he-ru model-info
he-ru setup --accept-model-terms
he-ru doctor
```

Отдельный репозиторий проекта —
[github.com/igor-markin/hebrew-live](https://github.com/igor-markin/hebrew-live).
Исходный код опубликован в нём. Для воспроизводимой установки из Git закрепи полный
SHA проверенного коммита:

```sh
uv tool install --python 3.12 'git+https://github.com/igor-markin/hebrew-live.git@COMMIT_SHA'
```

Замени `COMMIT_SHA` полным SHA опубликованного коммита; не устанавливай движущуюся
непроверенную ветку. Синтаксис описан в официальном разделе uv о
[Git source для tools](https://docs.astral.sh/uv/guides/tools/#requesting-different-sources).
Установка кода не скачивает веса моделей и не означает принятия их условий. Сначала
проверь источники командой `he-ru model-info`, затем запускай
`he-ru setup --accept-model-terms` только если принимаешь отдельные условия моделей,
после чего выполни `he-ru doctor`.

Окружение tool и общий download cache принадлежат uv; их пути показывают
`uv tool dir` и `uv cache dir`. Модели, записи, настройки и Hugging Face cache по-прежнему
следуют `HEBREW_LIVE_HOME` и перечисляются командой `he-ru storage`.

Вместо setup можно указать все три собственных совместимых локальных пути:

```sh
./run.sh doctor \
  --asr-model /полный/путь/mlx-whisper \
  --translation-model /полный/путь/mlx-lm \
  --vad-model /полный/путь/silero-vad.onnx
```

Это узкий контракт совместимости. ASR должен иметь формат MLX Whisper,
переводчик — формат MLX-LM и соответствовать plain-prompt и tokenizer-контракту
MiLMMT, VAD — интерфейс Silero VAD ONNX. Совпадение
структуры не доказывает совместимость, качество или безопасность: сначала запускай
`doctor`. Пользовательские пути должны быть вне управляемого каталога `models/`,
поэтому ими нельзя обойти его SHA-256 manifest. При смешанном наборе весь управляемый
manifest проверяется. Переключение моделей во время сессии при явных путях отключено.
Для custom-переводчика target-меню отражает allowlist контракта MiLMMT, а не
доказательство обучения или качества конкретных весов на каждом языке.

## Использование

```sh
./run.sh listen
./run.sh benchmark /полный/путь/к/аудио.wav
./run.sh devices
./run.sh doctor
./run.sh model-info
./run.sh languages
./run.sh report --output /tmp/hebrew-live-report.json
```

Параметры записи ставь после команды:

```sh
./run.sh listen --device 2 --direction he-en --start-paused
./run.sh listen --asr-backend multilingual
```

Приложение распознаёт речь на иврите и по умолчанию переводит на английский. В
настройках target можно менять во время записи. Уже принятый конвейером звук сохраняет
прежний target; звук, захваченный после упорядоченной границы, записывается в новую часть
сессии с новым target. Старые карточки, файлы, повторная обработка и архивные метаданные
не переименовываются. Язык интерфейса хранится отдельно: английский по умолчанию,
русский или иврит; иврит включает RTL. Клик вне настроек и Escape закрывают меню.

`./run.sh languages` печатает точный реестр. Базовая
[MiLMMT](https://huggingface.co/translate-studio/MiLMMT-46-4B-v1.0-4bit-MLX)
заявляет 46 языков, поэтому для источника на иврите доступны 45 target-языков:
арабский, азербайджанский, болгарский, бенгальский, каталанский, чешский, датский,
немецкий, греческий, английский, испанский, персидский, финский, французский, хинди,
хорватский, венгерский, индонезийский, итальянский, японский, казахский, кхмерский,
корейский, лаосский, малайский, бирманский, норвежский, нидерландский, польский,
португальский, румынский, русский, словацкий, словенский, шведский, тамильский,
тайский, тагальский, турецкий, урду, узбекский, вьетнамский, кантонский, упрощённый и
традиционный китайский. UI получает этот список из 45 target-языков и не предлагает
язык вне контракта MiLMMT. Вместе с проверенным исходным ивритом реестр продукта
содержит 46 разных языков.

Опциональный upstream multilingual Whisper имеет 99 языковых токенов в
[официальном tokenizer OpenAI Whisper](https://github.com/openai/whisper/blob/main/whisper/tokenizer.py),
но это возможность модели, а не проверенный контракт продукта. Базовый ASR —
Hebrew-fine-tune Ivrit.ai; live input остаётся ивритом. Старое явное направление
`ru-he` читается для совместимости CLI и архивов. Детерминированные тесты проверяют
prompts, границы, persistence, cache keys и metadata, но не качество MT на всех языках.

Публичный интерфейс поддерживает один режим публикации — меняющийся `draft`. Текст
может заметно исправляться по мере поступления речи. Это не заверенный транскрипт и не
профессиональный перевод.

## Данные и приватность

Новая source-установка и установленная команда по умолчанию хранят app-owned файлы в
`~/Library/Application Support/Hebrew Live CLI/`: `models/`, `logs/`,
`.local-settings/`, `cache/{uv,huggingface}/` и
`runtime/{.venv,python}/`. Сам source checkout остаётся там, куда его распаковали;
общий prerequisite `uv` в app-root не копируется.
Нужные только разработчику `node_modules/`, frontend build output и metadata
source control остаются в checkout; обычный пользователь получает уже собранные UI-assets.
`HEBREW_LIVE_HOME` — поддержанная замена app-root. Прямой запуск из wheel также
по умолчанию кладёт `HF_HOME` под этот корень, но уважает явно заданный в shell
`HF_HOME`; фактический путь покажет `he-ru storage`. Source launcher сам задаёт uv- и
Hugging Face-пути из выбранного app-root, чтобы не разносить app-owned cache по разным shell-defaults.

Установленная команда принимает глобальные `--models` и `--log-dir` перед subcommand,
например `he-ru --models /путь/models --log-dir /путь/logs storage`. Preview показывает
фактические пути и исключает явные overrides из предполагаемого root-owned удаления.
Shell-preview запускается до Python и поэтому явно отклоняет эти два CLI-флага; для
единого custom root используй `HEBREW_LIVE_HOME=/путь ./run.sh storage`.

Если в существующем checkout уже есть `.venv`, `.cache`, `models`, `logs` или
`.local-settings`, launcher сохраняет прежний source-local layout и ничего автоматически
не переносит. Для будущих записей можно явно задать другой корень через
`HEBREW_LIVE_HOME`. Точные эффективные пути показывают read-only команды:

```sh
./run.sh storage
./run.sh uninstall --dry-run
# Для установленного wheel или uv tool:
he-ru storage
he-ru uninstall --dry-run
```

`uninstall` только показывает план и ничего не удаляет. Для полного удаления закрой
приложение и проверь preview. Штатный Application Support root выделен приложению, и после
проверки содержимого его можно переместить в Корзину. В custom root могут быть посторонние файлы,
а legacy source root содержит checkout: проверь и удали только показанные app-owned подкаталоги, а сам
checkout перемещай лишь после сохранения нужных custom и untracked данных.
Если команда ставилась через `uv tool install`, выполни
`uv tool uninstall hebrew-live-cli`; общий `uv` не удаляй, если им пользуются другие
проекты. Внешние BYO-файлы из `--asr-model`, `--translation-model` и `--vad-model`
никогда не входят в managed deletion. Wheel в отдельной ручной venv удаляется её
installer-ом или вместе с этой venv.

Browser UI хранит в `localStorage` только светлую/тёмную тему. Эти site data принадлежат
профилю браузера, не входят в app-root и не могут быть перечислены CLI-preview. Для
буквально полного удаления очисти в privacy settings браузера данные loopback-origin
`127.0.0.1`, которые использовал Hebrew Live CLI. Общий `uv`, общие cache вне показанных
путей и Python, ранее установленные `uv` для других проектов, тоже останутся; удаляй их
только после проверки, что они больше никому не нужны.

В сессии могут быть аудио, распознанная речь, перевод и технические логи. Приложение
их не отправляет. Завершённую сессию можно удалить в архивном интерфейсе после
подтверждения; активная защищена. Автоматического срока хранения и гарантии безопасного
стирания нет. Подробнее: [PRIVACY.md](PRIVACY.md).

Отчёт `report` специально исключает аудио, текст разговора, логи, локальные пути,
настройки и приватный URL. Всё равно перечитай файл перед передачей. Аудио и логи не
передавай без явного согласования адресата и цели.

## Если что-то не работает

- `Model not installed` — снова выполни setup, чтобы восстановить закреплённый набор моделей.
- Ошибка целостности — не правь manifest вручную; сохрани отчёт и повтори setup.
- Нет микрофона — проверь разрешение macOS и список `./run.sh devices`.
- Нет UI — исходный экспорт или wheel неполон; пересобери frontend и пакет.
- Баннер о несовместимом снимке — сохрани шаги воспроизведения и отчёт; сам баннер не
  доказывает потерю сети.
- Импорт MLX падает после успешного frozen-check — сохрани текст import error и отдельно
  проверь локальное окружение. Launcher не называет это ошибкой Metal и не удаляет или
  не переустанавливает прошедшую check `.venv` автоматически; пересоздай локальное
  окружение осознанно перед повтором.

Код 64 означает неподдерживаемую платформу или отсутствие обязательного аргумента
setup; 69 — нет prerequisite/разрешения на repair, окружение неполно, MLX не импортируется
или Metal недоступен; 70 — `uv` сообщил об успешном sync, но frozen-check всё ещё не
проходит; 130 — пользователь отменил или прервал запуск. Ошибка `uv sync` и итоговая
команда иначе сохраняют собственный код завершения, бесконечных повторов launcher не
делает.

Ограничения, проверки и оставшиеся блокеры перечислены в
[docs/RELEASE_READINESS.md](docs/RELEASE_READINESS.md).
